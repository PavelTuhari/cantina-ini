# Пароли и ключи — не в ini, а в реестре под защитой

## Что было

В `cantina.ini` и `selftest.ini` открытым текстом лежали: ключ API
кассы (`PosApiKey`), секреты MIA (`MIAClientSecret`, `MIAApiKey`,
`MIAApiSecrect`), ключ веб-проверки (`licenseKey`), пароль кассира и
пароль схемы для самотеста (`Password`, `SchemaPassword`). Плюс в
комментариях — старый ключ лицензии, код авторизации, ключ API. Всё это
уезжало в резервные копии, в архивы, в переписку и в git.

## Что стало

Значение из ini уходит в реестр **текущего пользователя Windows**,
зашифрованное DPAPI (`CryptProtectData`), а в файле остаётся пометка:

```ini
PosApiKey=@secret:cantina.ini/General/PosApiKey
Password=@secret:selftest.ini/Login/Password
#licenseKey=@removed
```

Хранилище: `HKCU\Software\Unisim\Secrets`, значения `REG_BINARY`.
Расшифровать может **только тот же пользователь Windows на той же
машине** — ни копия куста реестра, ни другой пользователь, ни другая
машина ничего не прочтут. Закомментированные секреты не хранятся вовсе:
их значение заменяется на `@removed`.

Касса читает пометки сама: `TSecureIniFile` (`uSecrets.h/.cpp`)
подставлен вместо `TIniFile` в двух местах — `cantina.ini` (`ucLogin.cpp`)
и `selftest.ini` (`uSelfTest.cpp`). Любой `ReadString`, встретив
`@secret:`, идёт в хранилище; `ReadInteger`/`ReadBool` внутри зовут тот
же `ReadString`. Секрета нет — вернётся пустая строка, а не пометка:
пометка иначе ушла бы паролем в базу. Причина — в отладочный вывод
(`OutputDebugString`), запуску кассы это не мешает.

## Как перенести

```bash
cd D:\RAD_Tokyo\Sources\UAMenu

python -m pypos secrets migrate Win32\Debug\cantina.ini          # показать, что перенесётся
python -m pypos secrets migrate Win32\Debug\cantina.ini --yes    # перенести
python -m pypos secrets migrate Win32\Debug\selftest.ini --yes

python -m pypos secrets check Win32\Debug\cantina.ini            # все ли пометки читаются
python -m pypos secrets list                                     # что лежит в хранилище (имена)
```

Что считается секретом: ключи из списка `cfgtool.descriptions.SECRETS` и
всё, что похоже по имени (`pass`, `secret`, `apikey`, `token`,
`license…key`, `autorizationcod`). Флаги вроде `NrComandReportPass=true`
и `WalletPassTitle` секретами не считаются. Значения **никогда не
печатаются** — только имена и длины.

Файл переписывается на месте: строки без секретов остаются байт в байт
(в `cantina.ini` есть байты вне cp1251, поэтому разбор побайтовый),
резервной копии с открытыми паролями не создаётся.

Касса под **служебной учётной записью**: перенос надо делать под ней
же, либо с ключом `--machine` — тогда хранилище машинное
(`HKLM\Software\Unisim\Secrets`, нужны права администратора) и
расшифровать сможет любой пользователь этой машины.

Положить секрет руками, не набирая его в консоли:

```bash
echo значение> p.txt
python -m pypos secrets set cantina.ini/General/PosApiKey --file p.txt    # файл затирается
```

## Что важно понимать

* **Git-история.** `cantina.ini` версионируется, и в его истории
  пароли остались. Перенос в реестр не отменяет их утечки: ключи,
  которые были в файле, надо **сменить** у их источников (API кассы,
  MIA, лицензия).
* **Новая машина.** Файл с пометками переезжает, секреты — нет. На новой
  машине их кладут заново (`secrets set` или `migrate` из файла с
  открытыми значениями, который потом удаляется).
* **Резервная копия и архив.** FrontArchive кладёт ini в архив уже с
  пометками и дополнительно вычищает всё похожее на секрет
  (`Sources/FrontArchive`). Восстановленный из архива ini на другой
  машине без её собственных секретов работать с внешними службами не
  будет — так и задумано.
* **Старая «шифровка» цезарем** (`caesarEncrypt` в
  `uLoyalityAPICommunication.cpp`) для `APIKey` и `APIBaseURL` осталась
  как была: она записывает обфусцированное значение в ini через
  `WriteStrParam`. Если такое значение перенести в реестр, касса
  прочитает его оттуда и расшифрует тем же цезарем — работать будет, но
  правильнее заменить цезарь на хранилище. Это отдельная правка.

## Проверено

* `pypos.secrets` — 25 проверок на копиях настоящих `cantina.ini`
  (766 строк, cp1251, байт 0x98) и `selftest.ini`: перенос 5 + 2
  секретов, файл без --yes не меняется, в отчёте нет значений, в файле
  не осталось значений, прочие строки байт в байт, `resolve` возвращает
  исходные значения, повторный перенос ничего не трогает,
  закомментированные секреты заменены на `@removed`, тестовые записи
  убраны.
* Касса собрана с `uSecrets.cpp`; самотест с паролями из реестра — см.
  раздел акта в `Sources/FrontArchive/README.md`.
