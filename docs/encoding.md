# Кириллица в кассе: Windows Server и кодировка исходников

Снимок с сервера, с которого начался этот документ: в заголовке окна
`èàññèð Tolik` вместо `кассир Tolik`, в шапке грида `Êîä`, `Íàèìåíîâàíèå`
вместо `Код`, `Наименование`, пункт меню `8. ????????` вместо
`8. Отчёты` — и при этом `Категории`, `Кол-во официантов`, `Тип счёта`
показаны правильно. Это не три разные ошибки, а одна.

## 1. Что происходит

Касса — VCL-приложение, в котором часть строк живёт как `AnsiString`
(байты в кодировке CP1251), а часть — как `UnicodeString`. Каждый раз,
когда `AnsiString` попадает в элемент управления, Windows переводит байты
в Unicode **по системной кодовой странице той машины, где касса
запущена** (ACP, «язык программ, не поддерживающих Юникод»).

| Симптом на снимке | Что случилось |
|---|---|
| `Êîä` вместо `Код` | байты CP1251 прочитаны как CP1252: на сервере ACP = 1252 (английская или румынская системная локаль) |
| `8. ????????` | строка шла в обратную сторону, Unicode → ANSI, и русских букв в CP1252 не нашлось |
| `Категории` правильно | строка Unicode от начала до конца, ACP не участвует |

Вывод: сервер настроен не на русскую системную локаль. Исходники и база
тут ни при чём — тот же `UAMenu.exe` на машине с ACP 1251 показывает всё
правильно.

## 2. Что сделать на Windows Server

1. **Системная локаль — русская.** Панель управления → Региональные
   стандарты → вкладка «Дополнительно» (Administrative) → «Изменить язык
   системы» (Change system locale) → **Русский (Россия)**. Это настройка
   машины, не пользователя: действует для всех, кто входит по RDP, и для
   служб. Нужна перезагрузка.
2. **Не включать** флажок «Бета-версия: использовать Юникод (UTF-8) для
   поддержки языка во всём мире» в том же окне. С ним ACP становится 65001,
   и касса показывает кашу уже другого вида.
3. **Проверить** после перезагрузки:

   ```bat
   reg query "HKLM\SYSTEM\CurrentControlSet\Control\Nls\CodePage" /v ACP
   ```

   Ожидается `ACP    REG_SZ    1251`. Формат дат и чисел (вкладка
   «Форматы») может оставаться любым — он на буквы не влияет.
4. **Клиент Oracle — та же кодировка.** `NLS_LANG` 32-битного клиента, через
   который ходит касса: `RUSSIAN_CIS.CL8MSWIN1251` (язык и территория
   могут быть другими, важна часть после точки). Где задаётся: ключ
   `NLS_LANG` в `HKLM\SOFTWARE\WOW6432Node\ORACLE\KEY_<имя home>` для
   полного клиента, переменная среды `NLS_LANG` для Instant Client. Если
   там `AL32UTF8` или `WE8MSWIN1252`, данные из базы (названия товаров,
   заголовки колонок из `TMS_*`) придут в кассу в чужих байтах — и это
   будет выглядеть так же, как на снимке, но только для данных, а не для
   меню.
5. **Проверить кассу, а не верить реестру.** Запустить с коротким
   `selftest.ini` (`log`, `wait`, `shot`): в `selftest.log` строка
   `автовход: кассир …` должна читаться по-русски, снимок главной формы —
   с русским меню. Это и есть приёмочный тест локали.

Один случай, когда всё настроено, а каша осталась: касса запущена под
пользователем, у которого в профиле включён «UTF-8 worldwide» отдельно, или
через планировщик с другой учётной записью. Проверять `ACP` под той же
учётной записью, под которой работает касса.

## 3. Кодировка исходников

До 10.10.2026 исходники были в двух кодировках: 122 файла `.cpp/.h` в
CP1251 без BOM, 14 в UTF-8 с BOM. Компилятор bcc32 читает файл без BOM
по ACP машины сборки, с BOM — как UTF-8; на машине с русской локалью оба
варианта давали одинаковые байты, но любая другая машина сборки или
редактор, сохранивший файл «как UTF-8» без BOM, ломал литералы.

**Теперь все `.cpp/.h` — UTF-8 с BOM** (перевод сделан скриптом, байты
литералов после сборки те же). Правило на будущее:

* новый или правленый файл кассы сохранять **UTF-8 с BOM**; редактор без
  BOM — это тот же CP1251-файл, только хуже: компилятор прочтёт его как
  ANSI, и русские литералы в чеке станут кашей уже на этапе сборки;
* `.dfm` **не переводить руками**: их пишет IDE, нерусские символы в них
  хранятся как `#1050#1086…` или в кодировке IDE; 13 файлов `.dfm` с
  CP1251 так и оставлены;
* проверка одной командой, что кодировок снова не стало две:

  ```bat
  python tools\enc_survey.py
  ```

  (скрипт лежит рядом с документом в приватном репозитории; печатает число
  файлов по кодировкам и перечисляет `.cpp/.h` без BOM с кириллицей).

Что перевод исходников **не** решает: узкие литералы `"Код"` при
компиляции всё равно превращаются в байты ACP и при показе снова проходят
через ACP сервера. Поэтому пункт 2 обязателен, а единая кодировка
исходников делает сборку воспроизводимой на любой машине. Окончательное
избавление от зависимости — писать строки как `L"Код"` / `UnicodeString`
по мере правок; массово менять это сейчас не стали.
